# Global Project Overview (Ideal and General Project Goal)
- Study graph-based floor plan representations and survey existing generative approaches (HouseGAN++, LayoutDM, and transformer-based layout models)
- Implement a graph neural network encoder for floor plan layouts, enabling similarity-based retrieval from the Maticad dataset using FAISS
- Implement a constraint-aware layout generation model (diffusion-based or autoregressive) conditioned on partial inputs such as room count, types, and adjacency constraints
- Develop an iterative refinement loop: given a generated proposal, the model can incorporate user corrections and re-generate accordingly
- Evaluate results in terms of layout validity (structural constraint satisfaction), diversity (coverage of the design space), and retrieval accuracy

# Current State of the Project (Phase 1 - Retrieval)
Begin with RPLAN, since it directly provides raster images of floor plans.
This allows us to implement two complementary retrieval pipelines.
The first approach is vision-based:
- input image --> vision encoder (DINOv2) --> embedding extraction --> FAISS nearest-neighbor retrieval
This baseline captures visual and geometric similarity between floor plans.
For the second approach, inspired by ideas from the Graph2Plan paper and related graph-based methods, we would transform the floor plan images into structured graphs.
We can then apply a Graph Neural Network encoder (GCN/GAT/GraphSAGE of similar architectures), to obtain graph embeddings, which are then used for retrieval in the same manner. This second pipeline focuses on capturing topological and semantic relationships between rooms, rather than purely visual similarity.

Partial Layout Retrieval:
To better simulate realistic architectural design workflows, the retrieval system will be tested (one idea, other could be possible) on partial floor plans, where complete layouts are intentionally degraded by removing certain rooms or structural components. The goal is to valuate whether the model is able to infer missing information and retrieve complete floor plans that are still compatible with the given incomplete input. This setting is particularly important because it moves the problem closer to real-world scenarios, where designers often start from incomplete sketches or partially defined spatial constraints. In this context, the system is expected not only to retrieve visually similar layouts, but also to demonstrate an ability to complete missing semantic and structural information in a meaningful way.

Evaluation strategy:
The performance of the retrieval systems will be evaluated using both standard and
semantically meaningful metrics tailored to architectural layouts. We use Recall@K to measure whether relevant layouts appear within the top-K results, providing a general indication of retrieval effectiveness. In addition, we evaluate room-level semantic similarity by checking whether retrieved layouts match the query in terms of room types and overall composition. Spatial relationships are also considered through adjacency-based metrics, which assess whether key room connections are preserved. Furthermore, we measure how well retrieved layouts satisfy functional constraints such as room counts and required adjacencies. For graph-based representations, we optionally use structural metrics such as graph edit distance to quantify overall topological similarity between layouts.
