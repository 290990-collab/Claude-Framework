# High-Level Architecture

This document describes the overall flow of the project as currently implemented in the Python sources.

## Project Phases

The project is organized in two phases, only the first of which is partially implemented:

1. **Phase 1 — Retrieval** (in progress): given a (possibly partial) floor plan, return the top-k most similar layouts from RPLAN. Two complementary pipelines:
   - **Vision-based** (implemented): image → DINOv2 → PCA whitening → embedding → FAISS.
   - **Graph-based** (in progress, Jul 2026): RPLAN `.mat` metadata (`rType`/`rEdge`/`gtBoxNew`) → PyG graph → **GNN encoder** (GCN/GAT/GraphSAGE) trained with **InfoNCE contrastive** → embedding → FAISS. Graph extraction, dataset cache, feature-adjustment transforms, visualization, the **three GNN encoders**, the **InfoNCE training loop** and the **FAISS indexing + per-axis evaluation** (`src/graph/evaluation/graph_evaluate.py`, sharing the vision metrics core) are **done**; real training/eval runs via sbatch and the config layer (`GraphModelManager`) are next.
   - The two branches keep **separate FAISS indices** and are combined by **late, score-level fusion** (per-branch score normalization, then `α·ẑV + (1−α)·ẑG`, with α tuned on validation). See [.claude/ai/architecture_diagram.txt](.claude/ai/architecture_diagram.txt).
2. **Phase 2 — Generation** (not started): constraint-aware layout generation conditioned on partial inputs (room count/types, adjacencies) with an iterative refinement loop.

The Python codebase mirrors this split. The **vision pipeline** ([src/vision/](src/vision/)) is end-to-end functional and evaluable, and carries the results so far. The **graph branch** ([src/graph/](src/graph/)) was restarted in Jul 2026 and is now feature-complete for a first benchmark: graph extraction, the cached PyG dataset, the adjustment transforms, the three GNN encoders, the InfoNCE training loop and the retrieval evaluation (FAISS + per-axis metrics, plus a training-free histogram baseline) are implemented and verified; only the trained checkpoints (sbatch runs) and the config layer are missing. See "Graph branch" below. Both branches read RPLAN ground truth through the same shared core ([src/data/rplan_metadata.py](src/data/rplan_metadata.py), [src/evaluation/](src/evaluation/)), which is why that core lives outside `src/vision/`.

## Vision Retrieval Pipeline (implemented)

The active pipeline is encapsulated by `VisionRetrievalPipeline` in [src/vision/models/retrieval_model.py](src/vision/models/retrieval_model.py). Five sequential stages:

1. **Data loading** — [src/vision/data/loader.py](src/vision/data/loader.py) defines `RPLANDataset`, which globs PNGs under a directory and yields `(tensor, path)` pairs. The path is carried through the whole pipeline so every embedding can be mapped back to its source floor plan. `get_dataloader()` wraps it with `shuffle=False` to keep the index ↔ path mapping stable.
2. **Preprocessing** — [src/vision/data/preprocess.py](src/vision/data/preprocess.py) provides `ResizeWithPad` (aspect-preserving resize + white padding to a square canvas, so narrow plans are not deformed) followed by ImageNet normalization. The same `load_image()` helper is reused at query time to guarantee the query is in the same distribution as the indexed database.
3. **Encoding** — [src/models/vision_encoder.py](src/models/vision_encoder.py) wraps a HuggingFace DINOv2 (`small`/`base`/`large`) with the backbone frozen by default. The `[CLS]` token is taken as the global embedding; an optional projection head is exposed but disabled by default (an untrained projection would scramble the semantic structure of the CLS token). Output is always L2-normalized so cosine similarity reduces to inner product.
4. **Whitening (optional but important)** — `fit_whitening()` centers the database embeddings and applies PCA whitening. The motivation, encoded in the docstring, is that DINOv2 frozen on out-of-distribution data (RPLAN are synthetic semantic colormaps, not natural images) produces embeddings that collapse to a small region of the hypersphere, making top-k retrieval indiscriminate (all scores in [0.97, 0.99]). The fitted `(mean, matrix)` are saved alongside the embeddings and re-applied to queries inside `query()` — this is the invariant that lets the pipeline reload from disk and stay consistent.
5. **Indexing + query** — `build_index()` builds a `faiss.IndexFlatIP` over the (whitened, L2-normalized) embeddings; `query()` runs the same encode → whiten → search pipeline on a single image and returns ranked `{path, score}` dicts.

Persistence is handled by `_save()` / `load()` against a directory (default `embeddings/vision/`) containing `embeddings.npy`, `image_paths.json`, and (if fitted) `whiten_mean.npy` + `whiten_matrix.npy`. The presence of the whitening files is what flips query-time whitening on or off, so the loader is self-describing.

## Evaluation

The evaluation core is **shared by both branches** and lives outside `src/vision/`: [src/evaluation/relevance.py](src/evaluation/relevance.py) derives real relevance from the RPLAN `.mat` metadata, decomposed into **three independent axes** — composition (room-type histogram), topology (type-level adjacency) and geometry (footprint + area distribution) — exposed through `GalleryAxes` (vectorized per-axis similarity + exact equivalence classes); [src/evaluation/metrics.py](src/evaluation/metrics.py) provides the pure metric functions: graded **nDCG@K** (IDCG over the whole gallery) on every axis, plus binary **Recall@K / mAP@K** on the discrete axes (relevant = exact equivalence class; singleton queries excluded and counted). There is deliberately **no fused score, no weights, no threshold**, and metrics are computed **against the entire gallery**, not just the retrieved list — this replaced an earlier saturated design (June 2026 redesign). [src/vision/evaluation/evaluate.py](src/vision/evaluation/evaluate.py) wires it for the vision branch: queries sampled from an official split (`eval.split`, typically 2000 from `test`), gallery = the whole snapshot, self-match excluded in full mode; a `partial` mode degrades the query (room removal) and adds **self-recovery** (rank/MRR of the source plan, self *not* excluded). [src/graph/evaluation/graph_evaluate.py](src/graph/evaluation/graph_evaluate.py) wires the same protocol and the same metric functions for the graph branch. Details and benchmark results live in [.claude/ai/retrieval.md](.claude/ai/retrieval.md).

## Visualization

[src/vision/utils/retrieval_visualization.py](src/vision/utils/retrieval_visualization.py) is a standalone CLI that loads a saved index and produces query-vs-top-k composite PNGs under `results/visualizations/`. It does not participate in the retrieval logic; it consumes the same pipeline through `pipeline.load()` and `pipeline.query()` and renders the output.

## Execution Model

- Every leaf module is meant to be run as `python -m <module>` (e.g. `python -m tests.test_vision_retrieval`); there is no central CLI entry point.
- [scripts/submit_job.sh](scripts/submit_job.sh) is the SLURM wrapper for HPC runs: it activates the venv, exports W&B env vars, and invokes the chosen module.
- The vision pipeline is GPU-accelerated when available (`device = "cuda" if torch.cuda.is_available() else "cpu"`) and falls back transparently to CPU on login nodes.

## Graph branch (`src/graph/`) — started Jul 2026

The graph branch is no longer a stub. Graph extraction, the cached dataset, the feature-adjustment transforms, visualization, the three GNN encoders, the InfoNCE training loop and the retrieval evaluation (FAISS indexing + per-axis metrics + training-free baseline) are all implemented, verified end-to-end **and run**: the three encoders are trained and benchmarked against the baseline, and an OFAT ablation over 9 variants per encoder is complete (see *Results*). The remaining pieces are the config layer (`GraphModelManager`), late fusion with vision, and a partial-query mode on graphs.

**Implemented:**

- [src/graph/graph_builder.py](src/graph/graph_builder.py) — adapter from `RoomMeta` to PyG `Data`. It performs **no `.mat` I/O**: it calls `load_metadata` from the shared core, so the graph branch and the vision branch read the same ground truth through the same reader. Node features are **19-dim** (13 one-hot room type + 6 geometry: `cx, cy, w, h, area, aspect`), `edge_index` is **symmetrized** (`to_undirected`), `edge_attr` is the one-hot of the RPLAN relation type (0..9). Node geometry is derived **only from `boxes` (`gtBoxNew`)**, never from `footprint` (`gtBox`, swapped axes) — the axis trap is structurally excluded.
- [src/graph/graph_dataset.py](src/graph/graph_dataset.py) — `RplanGraphDataset(InMemoryDataset)`: builds every graph once and serializes it to `embeddings/graph/rplan/processed/graphs.pt`. **67,405 graphs** (48 PNGs have no `.mat` record and are skipped); official splits 47,126 / 10,152 / 10,127. Build takes 2m47s, reload ~15s — the cost avoided is re-reading the three aggregate `.mat` files (~35s per process), which would otherwise be paid at every epoch. Cached graphs are **raw** (no normalization, topology untouched), so one cache serves every ablation variant; transforms are applied on the fly via PyG's native `transform`. This mirrors the raw-embedding decision on the vision side. Filtering by `split` happens **in memory** and never reprocesses the cache.
- [src/graph/draw_graph.py](src/graph/draw_graph.py) — visualization + CLI. The `spatial` layout places each node at the **real room centroid** (already present in the node features), so the graph can be overlaid on the floor-plan PNG. That overlay is the builder's correctness test: every node lands inside its own room and edges match real adjacencies.

**The adjustment step ([src/graph/transforms.py](src/graph/transforms.py)) — implemented.** It lives in a PyG `transform` (toggleable for ablation), not in the builder: the cache stays raw and the adjustment is applied on the fly. Two transforms plus stats support: `NormalizeNodeGeometry` z-scores the 6 continuous columns (one-hot left at 0/1), clipping `aspect` first because its tail (37 on degenerate rooms vs one-hot ≤ 1) would otherwise skew mean/std, while `area` averages 0.047 and would be nearly inert without standardization; `RemoveSpuriousSelfLoops` drops the `(i,i)` edges present in the `.mat` (GCN/GAT add their own, so leaving them double-weights the node). `compute_geometry_stats(train)` derives mean/std/clip from the **train split only** (no leakage), saved to `.npz`; `build_node_transform(normalize, drop_self_loops, stats)` composes them per ablation flags. Verified: train mean~0/std~1 after z-score; test normalized with train stats has mean *near* but not exactly 0 (no leakage); self-loops 23/3000 → 0; `aspect_clip` p99 = 4.58. **Recentering `cx/cy` is not needed**: RPLAN centers every plan in the canvas (footprint center = 0.500 ± 0.001), verified. Rotation/reflection invariance is a **training-time augmentation** question (the graph counterpart of the vision flip/rot90), not a preprocessing one.

**The graph encoders ([src/graph/models/](src/graph/models/)) — implemented.** Interchangeable behind a shared contract, config-driven like `vision_encoders/`, but **trainable** (unlike the frozen vision encoders): `forward` propagates gradients. `base.py` holds a `BaseGraphEncoder(nn.Module, ABC)` with a **single point of variation** — the layer stack, node→graph pooling, projection and L2-norm all live in the base, so each encoder implements only `build_conv(in, out)`. `forward(data) → [num_graphs, out_dim]` is L2-normalized (cosine = inner product for FAISS, as on the vision side) and handles the un-batched single-graph case (`data.batch = None`). Defaults encode the domain: `pooling="add"` (preserves the room count — itself a relevance axis — which `mean` would normalize away) and `num_layers=2` (4–8 nodes, diameter 2–3, so deeper means over-smoothing). The three encoders differ only in the conv: `gcn.py` (`GCNConv`, isotropic baseline), `gat.py` (`GATv2Conv`, dynamic attention, the **only** one consuming `edge_attr` = the RPLAN relation type; heads averaged with `concat=False` to keep the width constant), `graph_sage.py` (`SAGEConv`, keeps self and neighbor representations separate, preserving the room-type identity). `build_graph_encoder(name, **kwargs)` selects from `GRAPH_ENCODER_REGISTRY` (`gcn|gat|sage`). Verified on a real batch: L2-normalized embeddings, gradients flow, GAT consumes `edge_attr`, `mean_max` doubles the internal width, single graph → `[1, out_dim]`. **`raw_skip` (Jul 28, 2026, on by default in the YAMLs):** the add-pool of the **raw** node features is concatenated to the pooled embedding before the projection (`proj` 128→147). With one-hot types, that pooled vector **is** the room histogram, so composition and geometry reach the output **by construction** and InfoNCE cannot degrade them, leaving the network's capacity for topology — the piece the random-weight ablation showed is the only thing training actually buys. It is an architecture flag: it changes `proj`'s shape, so evaluation must pass the same value to reload a checkpoint (hence `--raw-skip` / `--no-raw-skip` on both entrypoints).

**The training loop ([src/graph/training/](src/graph/training/)) — implemented.** Self-supervised **InfoNCE**: no relevance labels exist, so the positive pair is two augmented views of the same graph, with the other plans in the batch as negatives. `augment.py` provides the graph counterpart of the vision partial-retrieval masking — **node drop** (zeroes nodes and removes their edges), **edge drop**, **feature mask**, plus the symmetries and jitter added in the redesign below. A deliberate design point keeps the InfoNCE rows aligned: the views **preserve node count and the `batch` vector** (dropped nodes are zeroed and isolated, not removed), so both views yield the same B graphs in the same order; with `add`-pool a zeroed isolated node contributes 0, i.e. it is effectively removed. `train_gnn.py` holds the loop: `_train_epoch` (two views per batch → InfoNCE → backprop), `_val_loss` (deterministic augmentation for a comparable val curve), `train(cfg)` with early stopping on the valid split and best-weights saved to `<save_dir>/encoder.pt` — ⚠️ the selection criterion is the **retrieval probe**, not that val-loss (see the note below). Normalization statistics come from the **train split only** (no leakage), saved alongside as `geom_stats.npz`. Unlike the vision head — which trained on cached vectors with a frozen backbone — the GNN itself trains, so each epoch does a forward over the graphs (cheap: 4–8 nodes each); there is deliberately **no embedding cache** (embeddings change every epoch — which is exactly why the *graphs*, not the embeddings, are cached). Config is argparse-driven and shaped as `train(cfg)`, so wiring the future `GraphModelManager` is a change of config source, not of the loop. Smoke-tested on CPU (aligned views, decreasing train/val loss, save/load).

⚠️ **Checkpoint selection does not use the InfoNCE val-loss ([src/graph/evaluation/retrieval_probe.py](src/graph/evaluation/retrieval_probe.py), Jul 27, 2026).** The two disagree, and not mildly: ranking the encoders by val-loss gave the **inverse** of ranking them by retrieval (GAT had the best loss and the worst nDCG). The cause is intrinsic to the objective — InfoNCE is *instance discrimination*, so in a batch of 256 the many plans sharing the query's composition/topology (equivalence classes are huge: only 0.4% of plans are singletons on composition) are treated as **negatives** and actively pushed away, i.e. the loss penalizes exactly what the evaluation calls relevant. Optimizing it better can therefore make retrieval worse, and the production probe caught GAT doing precisely that: peak retrieval at **epoch 3**, then 20 epochs of monotone decline while the val-loss kept improving. `RetrievalProbe` replaces it with a mini-retrieval on the **valid** split (fixed sampled gallery, queries drawn from it, self excluded) run every `probe_every` epochs, driving best-checkpoint and early stopping; the val-loss is still computed, as a diagnostic only. The protocol is deliberately identical to the final evaluation — the accumulation helpers were extracted into `src/graph/evaluation/axis_metrics.py` and are shared by probe and `graph_evaluate.py`, so the metric that *selects* the weights and the metric that *judges* them are the same code. Per-axis ground truth is computed once at construction, so the probe costs ~2.6 s/epoch (~20% overhead). ⚠️ Probe values are **not** comparable with the final report (smaller gallery → different IDCG); they are for relative, paired comparison, which is what an ablation needs. `training_summary.json` is written next to the checkpoint (criterion, best score/epoch, hyperparameters) so variants can be compared without re-reading logs.

**Augmentation redesign (Jul 28, 2026)** follows one rule: *every augmentation declares an invariance, and that invariance must be checked against the ground truth*. Flip and rotation are **true** invariances — composition, typed adjacency and the geometric features are all exactly invariant under them — so they are free signal; `node_drop` is a **false** invariance for full retrieval (it changes composition, a relevance axis) but a true one for partial queries, so it is dosed knowingly. Added `geom_jitter`, `flip_prob`, `rot_prob` (params grouped in an `AugmentParams` dataclass). ⚠️ Symmetries are applied in **raw** coordinates: the geometry stats are not isotropic (`std(cy)/std(cx) = 1.24`), so swapping z-scored columns would distort the scale by ~25% — the transform de-normalizes, acts, re-normalizes. `feat_mask` became **per (node, column)** instead of per-column-across-the-batch, which merely shifted the whole space uniformly instead of creating a discriminative difficulty. The motivation was quantitative: with 5 nodes and `node_drop=0.1`, 59% of views lost no node at all, making the contrastive task nearly trivial; at 0.2 the share of graphs actually perturbed goes 51% → 75%.

**The retrieval evaluation ([src/graph/evaluation/graph_evaluate.py](src/graph/evaluation/graph_evaluate.py)) — implemented (Jul 17, 2026).** Argparse-driven twin of `train_gnn.py` (model flags must match training; the architecture is rebuilt through the training's own `_encoder_kwargs`, so checkpoint reload is correct by construction). Flow: reload `encoder.pt` + `geom_stats.npz` → **one forward over the whole gallery** → save row-aligned `embeddings.npy` + `names.json` (ready for late fusion) → FAISS `IndexFlatIP` → queries sampled from the test split (gallery = whole snapshot, self excluded) → the **same per-axis metrics as vision**, from the shared `src/evaluation/` core used as-is (accumulation helpers are a local copy — deliberate: no cross-branch refactor). Since a query embedding is already a gallery row, search is a single batched FAISS call. A `--baseline-hist` mode evaluates the training-free `type_histogram` baseline (no checkpoint; on composition it is the oracle by construction — verified 1.0). Ops: `scripts/graph/04_eval_gnn.sh` (model flags from the training YAMLs + eval params from [configs/graph_retrieval.yaml](configs/graph_retrieval.yaml); whitelist bridge so training-only keys never reach the eval argparse); both `03` and `04` carry the anti-Blackwell sbatch constraint. The branch needs **no Hugging Face / network access**: GNNs train from scratch, data is local, wandb is off by default. **Ablation modes (Jul 28, 2026):** both scripts take a second positional argument — `03 <enc> ablation` trains the 10 OFAT variants, `04 <enc> <variant>` / `04 <enc> ablation` evaluates one or all of them; no second argument means `base`, the historical behaviour. The two tables are deliberately different, because in evaluation only **architecture** flags matter (the checkpoint reloads by construction): of the 10 variants only `noskip` changes the network, so the rest need just `--variant`, which namespaces the checkpoint directory. `04` derives its `ablation` list **from disk** (directories holding an `encoder.pt`) rather than duplicating `03`'s list — one less pair of lists to keep in sync, and untrained variants are skipped with a warning instead of crashing the job.

**Results (Jul 27–28, 2026).** Final evaluation, 2000 test queries, full gallery, nDCG@10 as composition/topology/geometry: **GCN 0.934 / 0.789 / 0.938**, SAGE 0.916 / 0.766 / 0.943, GAT 0.915 / 0.761 / 0.938, versus the training-free histogram baseline 1.000\* / 0.643 / 0.894 (\*oracle by construction). With the `raw_skip` + augmentation fixes, GCN moves to 0.971 / 0.828 / 0.940 (composition mAP@10 0.632 → 0.847) while GAT loses topology — see the CLAUDE.md summary for the per-encoder breakdown. **Best current configuration: `gcn/tau02` at 0.972 / 0.826 / 0.940**, from evaluating the ablation winners and their `base` references on the test (6 paired runs, Jul 28). That round also **validated the probe as a selector** — the topology gain it predicted on the valid transferred to the test on all three encoders (+0.030 → +0.038 for GCN, +0.031 → +0.033 for SAGE, +0.012 → +0.046 for GAT) — and **refuted the temperature increase**: at fixed everything else, τ 0.2 → 0.3 costs 0.038 of topology, and τ = 0.5 is the worst variant on all three encoders. The false-negative estimate that motivated the raise (8.17% of the gallery shares a query's composition) measured the wrong axis: topology equivalence classes have a median size of 16 against composition's 3980, so softening the pressure on near negatives destroys the signal that topology retrieval depends on without buying anything back. The honest reading of these numbers comes from a **random-weights ablation**, measured with the probe (valid, 5000-plan gallery, 500 queries) and therefore **not** on the same scale as the test figures above — what matters is the comparison *within* it: add-pooling the raw features with *no network at all* scores 0.884 / 0.625 / 0.906 (mean 0.805) and randomly initialized GNNs 0.799–0.809, against 0.862 for trained GCN. So an untrained system is already at ~93% of the trained one: most of the score is the **architecture** — with one-hot types, `add`-pool *is* the room histogram, so composition comes for free and geometry nearly so — and training buys essentially one thing, **topology** (+0.100 for GCN, versus +0.012 on geometry). That also explains why peaks arrive after very few epochs (3–40 out of 150): on 4–8-node graphs with diameter 2–3 and 2 layers, learning to propagate 1–2 hops takes a few hundred steps. The right denominator for "does the GNN help" is therefore the random-weight GNN, not only the histogram baseline, and the branch's real value over that baseline is topology: nDCG 0.789 vs 0.643, but above all **Recall@1 0.507 vs 0.027**.

**Next:** late fusion with vision (the aligned `embeddings.npy` + `names.json` of all four systems are already saved — ⚠️ inner-join on names: 67,405 graphs vs 67,453 vision rows); a **partial** mode in `graph_evaluate` mirroring the vision one, where the graph's native node-drop robustness should pay off; a `GraphModelManager` (the config layer, mirroring `VisionModelManager` — once it exists the YAML→flag bridges in the scripts become redundant); **GIN** as a fourth encoder (the right inductive bias for topology); and a SimCLR-style throwaway projection head, which attacks the false-negative problem at its source instead of working around it.

⚠️ **Open question — evaluation circularity.** The relevance labels (composition/topology axes in `relevance.py`) are derived from `rType`/`rEdge`, which are **exactly** the graph branch's input (node features / edge_index). The graph is handed, as input, what the ground truth measures as output — so it is **not** an apples-to-apples comparison against vision, which must infer that structure from pixels. Three ways out: (1) declare it and present the graph branch as an **oracle / upper bound**; (2) evaluate the graph branch on the **geometry** axis only; (3) extract the graph **from the image** (Graph2Plan-style) so both branches start from pixels — the only option that makes late fusion genuinely meaningful, but out of scope for Phase 1. **Decision pending.**

The intended end-state for Phase 1 — a symmetric pair of retrieval pipelines (vision, graph) sharing the same metrics core — is now structurally in place: both branches index L2-normalized embeddings in `IndexFlatIP` and report the same per-axis tables, and both save row-aligned `embeddings.npy` + names, which is exactly the interface the score-level **late fusion** (`α·ẑV + (1−α)·ẑG`, per-branch score normalization) will consume.

**First paired vision-vs-graph comparison (Jul 28, 2026).** Both branches were evaluated on the *same* 2000 test-split queries with the same gallery and metrics — confirmed by both logs reporting identical singleton exclusions (10 composition, 313 topology). nDCG@10: **vision best-per-axis C 0.830 / T 0.662 / G 0.948** vs **graph GCN 0.934 / 0.789 / 0.938** (SAGE geometry 0.943). Three readings matter. (1) **Vision wins on geometry (0.948 vs 0.943)** — the only axis where the comparison is fair, since on composition/topology the graph is handed `rType`/`rEdge` as input; this is the honest signal in the table. (2) On topology the best visual encoder (0.662) barely beats the type-histogram baseline (0.643), which ignores adjacency entirely — reading connectivity off pixels is genuinely hard (a solid wall vs an opening is a handful of pixels). (3) The graph represents rooms as **bounding boxes**, so an L-shaped and a rectangular room with the same box are identical to it; wall thickness, openings and outline shape are information only vision has — and that **none of the three current axes measures**.

⚠️ **Realistic expectation for the fusion.** Taking the per-axis best across all systems (composition 1.000 from `hist`, topology 0.789 from GCN, geometry 0.948 from vision) yields mean 0.912 against 0.887 for GCN alone: **+0.025, almost entirely from the baseline's composition**, with vision contributing only ~+0.005–0.010. On the current metrics the fusion therefore moves little — not because vision is weak, but because the graph wins two axes by circularity and the axes do not measure what only vision sees. The value lies in **partial retrieval** (the branches fail differently: vision degrades with the pixels left, the graph is natively robust to node dropping) and in real-world applicability. Recommended implementation: **weighted concatenation** `[√α·v ; √(1−α)·g]` over L2-normalized embeddings — the inner product *is* `α·simV + (1−α)·simG`, so fusion needs **one FAISS index and one search** rather than merging candidates from two; normalize per-branch score scale first, and keep **RRF** (rank fusion, scale-free by construction) as the comparison baseline. Before building anything, measure complementarity from the already-saved embeddings (top-10 overlap, per-query nDCG correlation, oracle upper bound) — note the **inner join on plan names** is required: graph has 67,405 plans, vision 67,453 (48 PNGs lack a `.mat` record). Full write-up (metrics explained, comparison, five fusion methods) in `spiegazione_metriche_e_risultati_grafi.md`.
