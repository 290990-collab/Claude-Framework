# Structure of the Project

Core code lives under `src/`, split by branch:
- **`src/vision/`** — l'intera pipeline di retrieval vision (`data/`, `models/`, `evaluation/`, `training/`, `utils/`). È l'unico ramo attivo.
- **Core condiviso, fuori da `src/vision/`** (riusato dal futuro ramo grafi, quindi tenuto in `src/`): `src/data/rplan_metadata.py` (lettore dei `.mat` RPLAN), `src/evaluation/metrics.py` (metriche di retrieval encoder-agnostiche), `src/evaluation/relevance.py` (`GalleryAxes`, ground-truth di rilevanza per-asse).
- **`src/graph/`** — ramo grafi (**avviato, lug 2026**): `graph_builder.py`, `graph_dataset.py`, `transforms.py`, `draw_graph.py`, `models/` (encoder GCN/GAT/SAGE), `training/` (InfoNCE self-supervised), `evaluation/` (`graph_evaluate.py`: forward gallery → FAISS → metriche per-asse, + baseline training-free `--baseline-hist`). Si appoggia al core condiviso qui sopra (legge i `.mat` **solo** via `rplan_metadata`, non li riparsa). Config layer (`GraphModelManager`) ancora da scrivere.

Entry points:
- Each module exposes its own `main()` under `if __name__ == "__main__"` and is launched via `python -m <module>` (e.g. `python -m tests.test_vision_retrieval`).
- scripts/submit_job.sh — SLURM wrapper that activates the env and runs the chosen module.

## Vision encoders (intercambiabili)
- `src/vision/models/vision_encoders/` — encoder vision intercambiabili dietro un contratto comune.
  - `base.py` — `BaseVisionEncoder` (nn.Module + ABC): contratto `forward()->[B,D] L2-norm`, `build_transform()`, `embedding_dim`. Tutti gli encoder sono **frozen** (feature extraction). Helper di pooling condivisi: `gem_pool(tokens, p)` e `pool_global(natural, patches, pooling, gem_p)` (`POOLINGS = natural|mean|gem`).
  - `dinov2.py` — `DINOv2Encoder` (pooling configurabile, default [CLS]; normalizzazione ImageNet; `extraction_layer` via `output_hidden_states`). Ex `vision_encoder.py`.
  - `dinov3.py` — `DINOv3Encoder` (sottoclasse di DINOv2, inoltra `pooling`/`gem_p`/`extraction_layer`; checkpoint gated).
  - `siglip2.py` — `SigLIP2Encoder` (vision-language Google; natural = attention pooling `get_image_features`, mean/gem dai patch di `vision_model`; normalizzazione [0.5]x3, NON ImageNet; `extraction_layer` non applicabile).
  - `radio.py` — `RADIOEncoder` (NVIDIA, agglomerativo: distilla DINOv2+CLIP+SAM; `trust_remote_code`; forward ritorna `(summary, spatial)`, natural = summary / mean-gem sulle spatial; normalizza l'input internamente → transform a [0,1]; `embedding_dim` dedotta con forward di prova; `extraction_layer` non applicabile).
  - `ijepa.py` — `IJepaEncoder` (Meta, self-supervised predittivo; NO token [CLS] → natural = mean-pool patch / gem; normalizzazione ImageNet; solo taglie grandi ViT-H/g; `extraction_layer` via `output_hidden_states`).
  - `__init__.py` — `ENCODER_REGISTRY {name: classe}` + `build_encoder(name, **kwargs)`.
- `src/vision/models/vision_model_manager.py` — `VisionModelManager(config)`: costruisce l'encoder via registry da `config.model.name`, lo mette su device + eval, espone `.encoder` e `.transform`. **Niente optimizer/scheduler** (vision è frozen; quei pezzi saranno nel manager del ramo graph).
- `src/vision/utils/config.py` — `load_vision_config(path, overrides)`: carica `configs/vision_retrieval.yaml` e vi innesta i kwargs dell'encoder da `configs/vision_models/<name>.yaml`; `overrides` = lista dotlist (es. `model.kwargs.pooling=gem`) applicata per ultima → sweep senza editare i YAML. I 3 entrypoint (`tests.test_vision_retrieval`, `evaluate`, `retrieval_visualization`) raccolgono gli override con `parse_known_args`.

## Config del retrieval vision
- `configs/vision_retrieval.yaml` — config principale: `model.name` (selettore encoder), `model.variant` (etichetta per namespacing), device, `retrieval.*`, `whitening.*` (`enabled`/`eps`/`dim`), `head.*` (`enabled`/`hidden_dim`/`out_dim`, Fase 3), `training.*` (`epochs`/`lr`/`batch_size`/`temperature`/`views_per_plan`/`mask_fraction`/`augment`/`split_pool`), `eval.*` (`num_queries`/`seed`/`split`/`k_values`). `save_dir` namespaced per encoder+variante via `${model.name}/${model.variant}`.
- `configs/vision_models/{dinov2,dinov3,siglip2,radio,ijepa}.yaml` — preset per-encoder (kwargs del costruttore: `hf_name`, `image_size`, `pooling`, `gem_p`, e `extraction_layer` dove applicabile).
- **Cambiare encoder = cambiare una riga** (`model.name`); **sweep ablation = override CLI** (`model.variant=... model.kwargs.<knob>=...`).

## Preprocessing
- `src/vision/data/preprocess.py` — `ResizeWithPad` (condiviso, padding senza distorsione), `compose_transform(image_size, mean, std)` (per-encoder), `get_transform()` (default ImageNet, fallback), `load_image(path, transform)` (carica una query da disco). `src/vision/data/loader.py` — `RPLANDataset` + `get_dataloader()`.
- `src/vision/models/retrieval_model.py` — `VisionRetrievalPipeline(encoder, transform, device)`: agnostico all'encoder; usa il `transform` del modello per gallery e query (`load_query(path)`). **Embedding RAW disaccoppiati**: `extract_embeddings`/`_save` salvano il RAW (`embeddings.npy`); `prepare_index(head, whiten, whiten_dim)` applica al volo head opzionale → whitening opzionale → L2 e costruisce FAISS (stesse trasformazioni sulla query via `_apply_head`/`_apply_whitening`). Un solo RAW alimenta tutte le combinazioni (raw/whiten/head/head+whiten).

## Valutazione (vision)
- `src/data/rplan_metadata.py` — `RoomMeta` (include `split`) + `load_metadata(png)` + `get_split(png)`: metadati strutturali dai `.mat` (composizione/topologia/geometria) e split ufficiale RPLAN della pianta.
- `src/evaluation/relevance.py` — `GalleryAxes`: feature per-asse vettorializzate + similarità/classi di equivalenza su tutta la gallery.
- `src/evaluation/metrics.py` — `ndcg_at_k` (primaria), `recall_at_k`, `average_precision_at_k` (assi discreti).
- `src/vision/evaluation/evaluate.py` — orchestratore. Modalità **full** (query completa) o **partial** (guidata dal blocco `partial` del config). Accumulo per-asse condiviso (`_accumulate_axes`, flag `exclude_self`).

## Partial retrieval (vision)
- `src/vision/data/vision_partial_query.py` — costruzione query parziali: `select_rooms_to_remove(meta, strategy, params, rng)` (3 strategie: random/semantic/topology) + `render_partial_image(png, meta, removed_idx, open_boundary)` (affine griglia-256→px + flood-fill + cancellazione muri del bordo) + `make_partial_query(...)`. Solo ramo vision (nome esplicito per non confonderlo col masking del ramo graph futuro).

## Projection head (Fase 3 — vision)
- `src/vision/models/projection_head.py` — `ProjectionHead(in_dim, hidden_dim, out_dim)` (MLP `Linear→GELU→Linear`, uscita L2-norm) + `info_nce(za, zp, temperature)` (NT-Xent simmetrica, negativi in-batch) + `load_head(save_dir, ...)`.
- `src/vision/data/projection_pairs.py` — cache delle coppie positive **A+** (self-supervised): per ogni pianta di `training.split_pool` (train+valid) genera V viste degradate (`make_partial_query` random) + augmentation (`_augment`: flip/rot90) e le encoda col backbone frozen → `pairs.npz` (`anchors`, `positives`). `_PartialViewDataset` rende il rendering parallelo nei worker.
- `src/vision/training/train_projection.py` — allena la head su `pairs.npz` (vettori cachati, backbone frozen) con InfoNCE → salva `head.pt`. Iperparametri da `training.*` (τ=`temperature`, V=`views_per_plan`, ecc.).
- `src/vision/utils/config.py` — `transform_tag(cfg)`: etichetta del contributo attivo (`raw`/`whiten`/`whiten768`/`head`/`head+whiten`) per namespacing di log e visualizzazioni.
- Entrypoint/ordine in **`COMANDI.md`** (root); job numerati in **`scripts/vision/`** (`01_extract_raw`, `02_build_pairs`, `03_train_head`, `04/05_eval_*_full`, `06/07_eval_*_partial`): coprono la griglia pooling (natural/gem/mean) × trasformazione (raw/whiten/head/head+whiten). Ogni script: nessun argomento = tutti e 5 i modelli; un argomento = un solo modello (parallelizzazione).

## Ramo grafi (`src/graph/`)
- `src/graph/graph_builder.py` — adapter **`RoomMeta` → PyG `Data`**. Non fa I/O sui `.mat`: chiama `load_metadata` dal core condiviso. `build_graph(meta)`, `build_graph_from_png(png_path)`, costante `NODE_FEATURE_DIM = 19`.
  - **Node features (19)** = one-hot tipo stanza (13, da `room_types`) + geometria (6: `cx, cy, w, h, area, aspect`, da `boxes`, normalizzata su griglia 256).
  - **`edge_index`** da `edges`, **simmetrizzato** con `to_undirected` (PyG richiede entrambe le direzioni per il message passing). **`edge_attr`** = one-hot della relazione RPLAN 0..9 (10-dim); usabile da GAT (`edge_dim`), ignorato da GCN/SAGE.
  - **Attributi graph-level** (fuori dal message passing): `name`, `split`, `num_rooms`, `footprint_area`, `footprint_aspect`, `type_histogram` (quest'ultimo è la base della baseline training-free).
  - ⚠️ La geometria dei nodi usa **solo `boxes`** (`gtBoxNew`, `[x0,y0,x1,y1]`), mai `footprint` (`gtBox`, assi scambiati): la trappola degli assi è così strutturalmente esclusa. Del footprint si usano solo area/aspect, invarianti allo scambio.
- `src/graph/graph_dataset.py` — `RplanGraphDataset(InMemoryDataset)`: costruisce i grafi da tutti i PNG della gallery **una volta** e li serializza in `embeddings/graph/rplan/processed/graphs.pt` (117 MB). Build 2m47s → reload ~15s (il costo evitato è la lettura dei `.mat`, ~35s per processo). **67.405 grafi** (48 PNG senza record `.mat`, saltati); split ufficiali 47.126 / 10.152 / 10.127.
  - I grafi in cache sono **GREZZI** (nessuna normalizzazione, topologia intatta) → una sola cache serve tutte le varianti; le trasformazioni si applicano al volo col `transform` nativo PyG. Stessa logica dell'embedding raw sul ramo vision.
  - `split="train"|"valid"|"test"` filtra **in memoria** (via `data.split`, già dentro ogni grafo): **non** riprocessa la cache. `.names` dà la mappa indice → pianta per FAISS.
  - Gli attributi stringa (`name`, `split`) sopravvivono al collate PyG → dal batch si risale sempre alla pianta.
- `src/graph/draw_graph.py` — visualizzazione + CLI (`python -m src.graph.draw_graph 10002 --overlay`). `draw_graph(data, ax, layout, background_png, ...)`, `save_graph`, `draw_graph_grid`, `node_room_types(data)`.
  - Layout **`spatial`** (default): nodi ai **centroidi reali** (`cx, cy` sono già nelle feature) → il grafo ricalca la pianta e si sovrappone al PNG. Layout **`spring`**: sola topologia. Nodi colorati per tipo + legenda.
  - L'overlay è il **test di correttezza del builder**: ogni nodo cade dentro la sua stanza, gli archi coincidono con le adiacenze reali.
  - ⚠️ Da CLI ogni invocazione ricarica i `.mat` (~35s, `lru_cache` è per-processo): per molte piante, una sola invocazione `--grid` o un unico processo.
- `src/graph/transforms.py` — **fase di adjustment** come `transform` PyG (accendibile/spegnibile in ablation, **non** dentro il builder: la cache resta grezza, si applica al volo). Due trasformazioni + supporto statistiche:
  - `NormalizeNodeGeometry(mean, std, aspect_clip)` — z-score delle 6 colonne geometriche (l'one-hot del tipo resta 0/1). Ordine: prima **clip di `aspect`** al `aspect_clip`, poi z-score per colonna. Motivo: le scale sono incompatibili (`aspect` fino a **37** per stanze degeneri vs one-hot ≤ 1; `area` media 0.047 quasi inerte); senza standardizzazione un layer lineare sarebbe dominato da `aspect` e ignorerebbe `area`.
  - `RemoveSpuriousSelfLoops` — toglie gli archi `(i,i)` dei `.mat` (~46/8k) e la relativa riga di `edge_attr`; GCN/GAT aggiungono i self-loop da sé → altrimenti peso doppio sul nodo.
  - `compute_geometry_stats(train_dataset, aspect_percentile=99)` — media/std/clip calcolati **solo dal train** (no leakage: valid/test non contribuiscono); `save_/load_geometry_stats` serializzano in `.npz`. `aspect` clippato **prima** di media/std, coerente col runtime.
  - `build_node_transform(normalize, drop_self_loops, stats)` — compone secondo i flag di ablation (ogni pezzo opzionale → `None` = dataset grezzo); `Compose` se più d'uno. Sarà pilotato dal config del ramo graph.
  - Verificato: post-z-score sul train media~0/std~1; su **test** (stats del train) media *vicina* a 0 ma non esattamente 0 = no leakage; self-loop 23/3000 → 0; `aspect_clip` p99 = 4.58.
  - **NON serve ricentrare `cx/cy`**: RPLAN centra ogni pianta nel canvas (centro footprint = 0.500 ± 0.001), quindi le coordinate misurano davvero la posizione *dentro* l'appartamento. Invarianza a rotazione/riflessione: `cx/cy` **non** sono invarianti → materia di **augmentation nel training** (controparte del flip/rot90 vision), non di preprocessing.
- `src/graph/models/` — **encoder di grafo intercambiabili** dietro un contratto comune (registry config-driven, gemello di `vision_encoders/`). A differenza del vision, le GNN **si allenano** (no `_freeze`, `forward` propaga gradienti).
  - `base.py` — `BaseGraphEncoder(nn.Module, ABC)` con **un solo punto di variazione**: stack di layer, pooling nodi→grafo, proiezione e L2-norm vivono qui; ogni encoder implementa solo `build_conv(in, out) -> MessagePassing`. `forward(data)->[num_grafi, out_dim]` L2-norm (cosine = inner product per FAISS, coerente col vision); gestisce `data.batch=None` (singolo grafo). Argomenti: `in_dim=19, hidden_dim, out_dim, num_layers=2, pooling, dropout, raw_skip`. **`raw_skip`** (28 lug 2026, default `False` per retro-compatibilità dei checkpoint, `true` nei YAML): concatena l'add-pool delle feature **grezze** dei nodi all'embedding poolato prima della proiezione (`proj` 128→147). Motivo misurato: il solo add-pool grezzo, **senza rete**, fa già nDCG medio 0.805 contro 0.862 dell'allenato — con l'one-hot del tipo quella somma **è** l'istogramma delle stanze, quindi composizione e geometria arrivano all'uscita per costruzione e non sono degradabili da InfoNCE, lasciando la capacità della rete alla topologia (l'unico asse che il training compra davvero: +0.100 contro +0.056 e +0.012). Deve combaciare tra training ed eval: è cablato in `_encoder_kwargs`, in entrambi gli argparse e nei due ponti YAML→flag. Helper `global_pool(x, batch, pooling)`; `POOLINGS = add|mean|max|mean_max`. Default **`pooling="add"`** (preserva il conteggio stanze = asse di rilevanza; `mean` lo normalizza via) e **`num_layers=2`** (grafi 4-8 nodi, diametro 2-3 → più profondità = over-smoothing). Flag `uses_edge_attr` per-classe: `forward` passa `edge_attr` alla conv solo se True.
  - `gcn.py` — `GCNEncoder` (`GCNConv`): media pesata simmetrica dei vicini, isotropo, baseline. `uses_edge_attr=False`.
  - `gat.py` — `GATEncoder` (`GATv2Conv`, attenzione dinamica): **unico a usare `edge_attr`** (il tipo di relazione RPLAN 0..9). `heads` teste mediate con `concat=False` per tenere l'uscita = `out_channels`. `heads/edge_dim/attn_dropout` impostati **prima** di `super().__init__` (build_conv li legge quando la base costruisce lo stack). `uses_edge_attr=True`.
  - `graph_sage.py` — `GraphSAGEEncoder` (`SAGEConv`): separa la rappresentazione del nodo da quella aggregata dai vicini → preserva l'identità del tipo (l'one-hot non si diluisce nella media). Param `aggr` (`mean` default). `uses_edge_attr=False`.
  - `__init__.py` — `GRAPH_ENCODER_REGISTRY` (`gcn|gat|sage`) + `build_graph_encoder(name, **kwargs)`. Verificato su batch reale: emb [B,out_dim] L2-norm, gradienti fluiscono, GAT consuma `edge_attr`, `mean_max` raddoppia la larghezza interna, singolo grafo → [1,out_dim].
- `src/graph/training/` — **training self-supervised InfoNCE** dell'encoder (le GNN si allenano, a differenza del backbone frozen del vision).
  - `augment.py` — augmentation di grafo (controparte del masking partial vision). Parametri raccolti in **`AugmentParams`** (dataclass, `from_cfg(cfg)`): `node_drop`, `edge_drop`, `feat_mask`, `geom_jitter`, `flip_prob`, `rot_prob`. **Principio guida documentato nel modulo**: ogni augmentation dichiara un'invarianza, e va confrontata con la ground truth — **flip/rot sono invarianze VERE** (composizione, topologia e geometria sono *esattamente* invarianti a rotazioni/riflessioni → guadagno puro), `geom_jitter` quasi vera, `edge_drop` parziale, **`node_drop` FALSA sul full retrieval** (cambia la composizione) ma vera sul partial. ⚠️ Le simmetrie si applicano in coordinate **grezze**: le stats RPLAN non sono isotrope (`std(cy)/std(cx)=1.24`, `std(h)/std(w)=1.26`), quindi scambiare colonne z-scorate falserebbe la scala del ~25% → `augment_view(batch, params, gen, geom_stats)` de-normalizza, trasforma, ri-normalizza (con `geom_stats=None`, dataset grezzo, applica dirette). Riflessione `cx→1-cx`; rotazione `(cx,cy)→(1-cy,cx)`, `(w,h)→(h,w)` con k∈{1,2,3} estratto **per grafo** (non per nodo). `feat_mask` è **per-cella (nodo, colonna)**, non più per-colonna-globale-sul-batch. Le viste mantengono numero nodi e vettore `batch` → righe InfoNCE allineate. Verificato: rotazione simmetria esatta (area/aspect invariati, 4 rotazioni = identità), one-hot e archi intatti, `node_drop` 0.1→0.2 porta i grafi che perdono un nodo dal 51% al 75%.
  - `train_gnn.py` — `info_nce(za, zp, tau)` (NT-Xent simmetrica, gemella del vision, su vettori L2-norm); `_train_epoch` (due viste per batch → InfoNCE → backprop); `_val_loss` (augmentation **deterministica** via generator riseminato a seed fisso → val-loss confrontabile tra epoche, ora **solo diagnostica**); `train(cfg)` con **early stopping** sul valid + salvataggio dei pesi migliori in `<save_dir>/encoder.pt` + `training_summary.json` (criterio, best score/epoca, iperparametri → confronto OFAT senza rileggere i log). **Il criterio di selezione è l'nDCG della `RetrievalProbe`, non la val-loss** (`--probe-every N`, `--probe-queries`, `--probe-gallery`, `--probe-k`, `--select-criterion mean|composition|topology|geometry`): le due grandezze divergono — nel run del 17 lug 2026 la classifica per val-loss era l'**inverso** di quella per retrieval (GAT loss migliore 2.08 / nDCG peggiore; GCN loss peggiore 2.73 / nDCG migliore), perché InfoNCE allontana anche le piante simili finite nello stesso batch, cioè proprio i rilevanti. Punteggio di selezione sempre "più alto = meglio" (nel fallback `--probe-every 0` è la val-loss **negata**); le epoche senza sonda non fanno avanzare la pazienza (che quindi conta **sonde**, non epoche). Se la sonda non gira mai (`probe_every > epochs`) i pesi finali si salvano lo stesso ma con un avviso esplicito: non sono stati selezionati. **Confermato in produzione (job 74096, 27 lug 2026):** GAT tocca il massimo di retrieval all'**epoca 3** e poi peggiora per 20 epoche mentre la val-loss continua a scendere; il calo è su composizione (0.890→0.858) e topologia (0.714→0.695), non sulla geometria (0.927→0.932) — cioè esattamente sugli assi con grandi classi di equivalenza, dove i "negativi" di InfoNCE sono in realtà rilevanti. Statistiche di normalizzazione dal **solo train** (no leakage) → `<save_dir>/geom_stats.npz`. `_encoder_kwargs(cfg)` raccoglie i param specifici (heads/edge_dim per GAT, aggr per SAGE). Config via argparse strutturata come `train(cfg)`: agganciare il futuro `GraphModelManager` = cambiare la sorgente della config, non il loop. `wandb` opzionale. **Differenza chiave dal vision**: qui la rete si allena → forward sui grafi ogni epoca (grafi piccoli, veloce); niente cache degli embedding (cambierebbero a ogni epoca — per questo si cachano i grafi grezzi, non gli embedding). Smoke test CPU verde (viste allineate, train/val-loss scendono, save/load).
- `src/graph/evaluation/graph_evaluate.py` — **valutazione retrieval del ramo graph** (lug 2026), entrypoint argparse-driven come `train_gnn.py`: `python -m src.graph.evaluation.graph_evaluate --encoder sage --variant base` (i flag del modello devono combaciare col training per ricaricare il checkpoint).
  - Flusso: ricarica `encoder.pt` + `geom_stats.npz` dal `save_dir` del training (le statistiche NON si ricalcolano) → forward **una volta** su tutta la gallery (67.405 grafi, `DataLoader shuffle=False`) → salva `embeddings.npy` + `names.json` allineati (per la late fusion col vision) → FAISS `IndexFlatIP` → query campionate dallo split (`--split test` default, gallery sempre intera, self escluso) → **metriche per-asse contro l'intera gallery** (nDCG@K su tutti gli assi; Recall/mAP@K sugli assi discreti), stessa tabella del vision.
  - Le funzioni numeriche vengono dal core condiviso `src/evaluation/{metrics,relevance}.py` **usate as-is**; gli helper di accumulo/stampa sono una **copia locale** di quelli del vision (scelta deliberata: i rami restano autonomi, niente refactor cross-ramo — vedi memoria `feedback-no-cross-branch-refactor`). Dal 27 lug quella copia locale vive in `src/graph/evaluation/axis_metrics.py` (estratta da qui) perché la condividono **due** chiamanti dentro il ramo graph: questa valutazione e la sonda del training.
- `src/graph/evaluation/axis_metrics.py` — helper di accumulo/stampa per-asse del ramo graph: `new_metrics(k_values)`, `accumulate_axes(...)` (nDCG su tutti gli assi + Recall/mAP sui discreti, `exclude_self` per il futuro partial), `mean_metric`, `print_axis_tables`. Esiste per garantire che la metrica che **seleziona** i pesi (sonda) e quella che li **giudica** (eval finale) siano letteralmente lo stesso codice.
- `src/graph/evaluation/retrieval_probe.py` — **`RetrievalProbe`**: mini-retrieval sul valid usato durante il training per scegliere il checkpoint. `build(dataset, num_queries, gallery_size, k, seed, batch_size)` campiona una gallery fissa dal valid e calcola **una volta sola** la `GalleryAxes` (il pezzo caro: lettura `.mat`); `score(encoder, device)` fa forward → prodotto scalare esatto su embedding L2-norm (equivalente a `IndexFlatIP`, a questa scala non serve un indice) → `accumulate_axes`, e ritorna `ndcg_/recall_/map_` per asse + `mean`. `selection_value(scores, criterion)` estrae il numero di selezione, `format_scores` la riga di log. Preserva il training-mode dell'encoder. Costo misurato: **2.6 s/epoca** a 500 query/5000 gallery (≈20% di overhead), build 30 s una tantum. ⚠️ I valori assoluti **non** sono confrontabili col report finale (gallery più piccola → IDCG diverso): servono a confrontare epoche e configurazioni tra loro, e siccome le query sono **fisse** il confronto è appaiato, quindi molto più sensibile di quanto suggerisca l'errore standard. Query **sempre dal valid**, mai dal test.
  - **`--baseline-hist`**: baseline training-free = `type_histogram` L2-norm (13-dim) al posto della GNN, nessun checkpoint richiesto, salva in `embeddings/graph/hist/<variant>/`. Valida l'idraulica FAISS+metriche; sulla composizione è l'oracolo per costruzione (nDCG/Recall=1.0, verificato).
  - A differenza del vision non rifà il forward della query: l'embedding della query è già una riga della gallery → ricerca **batched** in un'unica chiamata FAISS.
  - ⚠️ Stampa il caveat di circolarità: composizione/topologia derivano dagli stessi `rType`/`rEdge` in input alla GNN → su quegli assi il graph va letto come upper bound.
  - Smoke test verdi (CPU): baseline-hist end-to-end (50 query, composizione=1.0, idraulica ok) + percorso GNN con checkpoint SAGE random (forward 67k grafi, ricarica pesi, tabella coerente).
- `configs/graph_models/{gcn,gat,graph_sage}.yaml` — **ricette complete e auto-contenute** (una per encoder), chiavi = 1:1 con gli argomenti di `train_gnn.py`.
